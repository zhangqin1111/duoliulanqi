# 多模型去伪存真情报报告专业改造方案

## 0. 产品定调

这份报告不能像普通 AI 汇总，也不能像单纯模型评测。它应该像一个“事实黑匣子系统”输出的情报级结论：用户只问一句话，系统帮他完成问题补全、多模型交叉审讯、差异追问、污染剔除、证据收敛和最终溯源。

推荐产品概念：

`Fact Black Box · 多模型事实黑匣子`

推荐报告名称：

`多模型去伪存真情报报告`

推荐副标题：

`基于多 AI 交叉验证、差异追问、污染剔除与证据链收敛的溯源分析`

报告的核心卖点：

- 不是“哪个 AI 回答更好”，而是“用户的问题到底应该相信什么”。
- 不是“把多个回答揉在一起”，而是“把 AI 当作证人逐轮审讯”。
- 不是“生成漂亮文章”，而是“生成可追溯、可质疑、可复核的判断链”。
- 不是“炫技图表堆砌”，而是“每个图表都服务于可信度判断”。

## 1. 设计原则

### 1.1 先结论，后证据，再解释模型

报告打开后的 10 秒内，用户必须看到四件事：

- 最终判断是什么。
- 这个判断有多可信。
- 主要争议点在哪里。
- 哪些内容被系统剔除了。

模型表现只能作为可信度支撑，不能喧宾夺主。用户买单的是“判断力”，不是“模型打分作文”。

### 1.2 用审讯逻辑替代总结逻辑

报告叙事不应是“模型 A 说了什么、模型 B 说了什么”。专业版本应改成：

- 原始问题是否足够明确。
- 系统如何补全成可分析问题。
- 各模型给出了哪些可拆解 claim。
- claim 之间哪里一致，哪里冲突。
- 对冲突点如何继续追问。
- 哪些回答属于事实，哪些属于推测，哪些属于 AI 污染。
- 最终留下来的证据如何形成结论。

### 1.3 把结论分层，不假装绝对正确

报告中所有结论必须被分成四类：

- `强结论`：多模型一致，且逻辑链完整。
- `弱结论`：有一定交叉支持，但仍缺少外部证据。
- `污染结论`：疑似由幻觉、套话、时间错配、提示词诱导生成。
- `待核验结论`：不能直接采用，需要人工检索或外部来源验证。

这会显著提升专业感，因为专业报告最重要的不是“说得肯定”，而是“知道哪里不能肯定”。

### 1.4 图表必须有判断功能

每个图表都要回答一个问题：

- 可信度仪表盘：最终结论能信多少。
- 事实时间轴：事情是如何演化的。
- 争议热力图：模型到底在哪些点上冲突。
- 证据漏斗：系统剔除了多少噪音。
- 差异桑基图：差异从哪些模型流向哪些原因。
- 模型雷达图：哪个模型在本题中更像可靠证人。
- 风险矩阵：结论被误用会造成什么后果。

## 2. 报告信息架构

### 2.1 第一屏：战情驾驶舱

目的：让用户第一眼感到“系统已经替我审过一遍”。

核心模块：

- `一句话裁决`：直接回答用户问题，不绕弯。
- `可信度分数`：0 到 100，给出等级和原因。
- `结论状态`：强结论、弱结论、存在分歧、信息不足。
- `核心矛盾`：一句高级但准确的结构性表达。
- `最大不确定性`：当前最影响判断的未知项。
- `证据资产统计`：原始 claim 数、交叉确认数、差异点数、污染剔除数。

推荐文案结构：

```text
核心裁决：
当前材料支持“高概率成立”的判断，但关键细节仍存在时间口径与事实来源错配。

核心矛盾：
多模型在主线叙事上趋同，但在事实坐标、时间边界和因果解释上出现结构化失配。

最大不确定性：
缺少外部一手来源核验，部分结论仍停留在模型间互证阶段。
```

视觉设计：

- 背景使用浅灰白基底，叠加微弱网格和玻璃噪点。
- 中央是大号结论卡，右侧是环形可信度仪表盘。
- 下方是三枚状态灯：事实强度、分歧强度、污染风险。
- 可信度分数使用大字号，形成“仪表盘压迫感”。

### 2.2 第二屏：问题补全与分析任务书

目的：解释系统如何把用户的一句话变成可审讯的问题。

内容：

- 用户原始问题。
- 系统补全后的分析问题。
- 本轮需要模型回答的材料清单。
- 本轮禁止模型做的事。

补全策略：

- 用户没有给日期时，只使用“最近、当前、近期”，不强行补具体年月。
- 用户给了明确日期时，严格保留用户日期，不扩写时间范围。
- 用户只给关键词时，补全为“请提供可用于后续多模型对比报告的分析素材”，而不是替用户直接下结论。
- 补全的目标是拿到报告材料，不是让模型写最终报告。

推荐展示：

```text
原始问题：
郭德纲最新舆论

系统补全：
请围绕“郭德纲最近舆论”提供一份可用于多模型对比和追根溯源分析的材料。请重点包含：最新舆论事件、争议焦点、不同观点、时间脉络、可核验事实、疑似谣言或不确定信息、各类说法的可能来源。不要泛泛总结，不要补充无法确认的具体日期。
```

图表建议：

- `问题转译卡`：左侧原始问题，右侧补全任务，中间用箭头连接。
- `任务约束标签`：最近、可核验、禁止脑补、禁止泛泛总结。

### 2.3 第三屏：事实脉络与证据地图

目的：让用户看清事情的时间线和事实支撑。

内容：

- 多模型共同确认的事实。
- 单模型提出但未交叉确认的事实。
- 明确冲突的事实。
- 无法确认但可能重要的线索。

事实状态定义：

- `confirmed`：至少两个模型支持，且没有明显冲突。
- `disputed`：模型之间说法不一致。
- `uncertain`：只有单模型提及或证据不足。
- `polluted`：疑似幻觉、套话、错误日期、过度推断。

图表建议：

- `事实时间轴`：绿色代表确认，黄色代表待核验，红色代表冲突，灰色代表污染。
- `证据矩阵`：行是事实点，列是模型，单元格显示支持、反对、未提及、冲突。
- `事实权重条`：显示每个事实被多少模型支持，以及是否经过追问确认。

### 2.4 第四屏：争议焦点热力图

目的：把“AI 不一致”变成可理解的争议地图。

争议分类：

- `事实差异`：事件、人物、地点、数据不一致。
- `时间差异`：日期、先后顺序、时效边界不一致。
- `口径差异`：同一事实的描述角度不同。
- `因果差异`：对原因和影响的解释不同。
- `推理差异`：逻辑链条不同，结论来源不同。
- `污染疑似`：模型可能在编造、套模板、受提示词牵引。

热力图设计：

- 行：争议点。
- 列：模型。
- 色彩：蓝色代表支持，橙色代表保留，红色代表冲突，灰色代表未提及。
- 点击色块展开该模型原文摘录和系统追问记录。

专业展示文案：

```text
本轮差异并非简单观点不同，而是集中出现在三个层面：
第一，事实坐标不一致，模型对同一事件的时间边界处理不同。
第二，因果链路不一致，部分模型把舆论现象直接归因于单一事件。
第三，污染因子不一致，部分回答混入未经验证的推测性表达。
```

### 2.5 第五屏：差异详情侦查台

目的：满足用户点击“查看差异详情”的需求，并让差异可审查。

每个差异卡字段：

```json
{
  "id": "D1",
  "title": "争议焦点标题",
  "type": "事实差异 | 时间差异 | 口径差异 | 因果差异 | 污染疑似",
  "severity": "high | medium | low",
  "why_it_matters": "为什么这个差异会影响最终判断",
  "model_claims": [
    {
      "model": "Kimi",
      "claim": "模型说法",
      "evidence_level": "强 | 中 | 弱",
      "risk": "潜在风险"
    }
  ],
  "followup_question": "系统对所有模型的追问",
  "followup_summary": "追问后的合并结论",
  "pollution_removed": ["被剔除的污染项"],
  "retained_judgment": "剔除污染后的保留判断"
}
```

交互设计：

- 默认只展示差异标题、严重度、影响说明。
- 点击展开后显示模型分歧、追问记录和剔除理由。
- 高风险差异用红色边框，待核验差异用琥珀色标签。
- 支持“只看高风险差异”和“只看已剔除污染”筛选。

### 2.6 第六屏：去伪存真证据漏斗

目的：证明系统不是总结，而是在过滤。

漏斗阶段：

1. `原始回答池`：所有模型第一轮回答拆出的 claim。
2. `交叉确认池`：多个模型共同支持的 claim。
3. `差异追问池`：针对冲突点追问后的 claim。
4. `污染剔除池`：剔除 AI 幻觉、套话、时效错配、过度推断。
5. `最终证据池`：可用于形成报告结论的 claim。

图表字段：

```json
{
  "raw_claims": 28,
  "cross_checked": 16,
  "followup_retained": 11,
  "pollution_removed": 7,
  "final_evidence": 6
}
```

展示文案：

```text
系统从 28 条原始 claim 中识别出 9 条跨模型一致信息、5 条高风险冲突信息和 7 条污染疑似信息。经过二次追问与污染剔除后，最终保留 6 条可支撑判断的核心证据。
```

污染类型：

- `幻觉补全`：模型给出材料中不存在的具体事实。
- `时间污染`：把旧信息当作最新信息。
- `口径漂移`：同一事件在不同段落中定义不一致。
- `安全套话`：大量免责声明遮蔽有效信息。
- `推理跃迁`：从弱事实直接跳到强结论。
- `来源错配`：把无法核验的信息包装成确定事实。

### 2.7 第七屏：模型证人画像

目的：把模型能力评价从“谁更好”改成“本题中谁更可信”。

模型评价维度：

- `事实保真度`：是否少编造。
- `时间敏感度`：是否正确处理最近、当前、指定日期。
- `逻辑自洽度`：论点和论据是否闭合。
- `信息密度`：有效内容占比。
- `可核验性`：是否给出可验证线索。
- `污染控制`：是否少套话、少臆测、少安全废话。
- `追问响应力`：被追问时是否能修正或解释差异。

图表建议：

- `模型雷达图`：展示每个模型在本题中的能力形状。
- `对齐税条形图`：废话、规避、套话占比。
- `证人可信度卡`：把模型比喻为证人，标注“可靠证人、谨慎证人、发散证人、污染风险证人”。

注意：

模型评价必须放在主结论之后，不能让用户误以为报告重点是模型榜单。

### 2.8 第八屏：源头分析与最终裁决

目的：完成用户提出的“追根溯源”和“去伪存真”。

内容结构：

- `源头判断`：差异最可能来自哪里。
- `污染剔除后结论`：去掉 AI 生成污染后的判断。
- `证据强度说明`：哪些支持结论，哪些削弱结论。
- `仍需外部核验`：哪些不能由多模型互证解决。
- `行动建议`：下一步如何问、如何查、如何导出。

源头分类：

- `事实源头不足`：模型都缺少可靠外部材料。
- `时间边界不同`：模型理解的“最近”不一致。
- `检索能力差异`：不同模型能抓到的信息范围不同。
- `安全策略干扰`：模型因平台策略回避或模糊回答。
- `训练语料偏置`：模型对人物、事件、行业有历史认知偏差。
- `提示词诱导`：系统补全或用户问题导致模型过度发散。

最终裁决模板：

```text
最终裁决：
基于本轮多模型交叉验证，当前更稳妥的判断是：{结论}。

可信依据：
该判断主要来自 {N} 个模型共同确认的事实、{M} 次差异追问后的收敛结果，以及对 {K} 类污染因素的剔除。

保留意见：
由于 {不确定因素} 尚未被外部一手来源验证，本报告不建议将相关细节作为确定事实传播。
```

## 3. 视觉系统升级

### 3.1 整体气质

关键词：

- 情报室。
- 事实黑匣子。
- 咨询公司。
- 轻科幻。
- 高信息密度。
- 可审查的专业感。

不要做成：

- 普通 Markdown 报告。
- 简单白底长文。
- 一堆卡片无主次。
- 过度花哨但没有判断功能。

### 3.2 色彩系统

建议使用浅色高级情报风：

```css
:root {
  --report-bg: #f4f1ec;
  --report-panel: rgba(255, 255, 255, 0.82);
  --report-ink: #202124;
  --report-muted: #7a746d;
  --report-blue: #356bff;
  --report-cyan: #40c4ff;
  --report-amber: #ffad33;
  --report-red: #ff5d5d;
  --report-green: #42c67a;
  --report-line: rgba(32, 33, 36, 0.1);
}
```

颜色语义：

- 蓝色：可信、收敛、系统判断。
- 琥珀色：待核验、不确定。
- 红色：冲突、污染、高风险。
- 绿色：多模型确认。
- 灰色：未提及、低证据、被剔除。

### 3.3 字体与排版

推荐层级：

- 报告标题：28 到 34px，粗字重。
- 一句话裁决：22 到 28px，强视觉中心。
- 模块标题：16 到 18px。
- 正文：13 到 15px，保持阅读密度。
- 图表标签：11 到 12px。

排版原则：

- 每屏只允许一个视觉主角。
- 结论卡大，解释卡小。
- 数字要大，原因要短，证据可展开。
- 长段落必须拆成“裁决、依据、风险、下一步”四类。

### 3.4 动效设计

动效要像系统在做情报分析，而不是普通弹窗动画。

建议动效：

- 报告打开时，可信度环形仪表盘从 0 扫描到目标分数。
- 证据漏斗逐层收窄，污染项逐个淡出。
- 争议热力图色块按严重度依次点亮。
- 差异详情展开时，模型说法从左右滑入，最终判断居中收敛。
- 时间轴节点 hover 时，连线发光并显示原始模型片段。

避免：

- 到处弹跳。
- 持续闪烁。
- 动效慢到影响阅读。
- 没有信息含义的装饰动画。

## 5. Prompt 升级方向

### 5.1 总控 Prompt

```text
你不是在写普通 AI 对比报告。
你是一名多模型事实审讯官、舆情情报分析师和证据链架构师。

你的任务不是判断哪个模型更会写，而是围绕用户原始问题生成一份“去伪存真情报报告”。

优先级：
1. 先回答用户真正关心的问题。
2. 再说明结论如何从多模型回答、差异追问、污染剔除中推导出来。
3. 最后评价各模型在本题中的可信度表现。

必须区分：
- 强结论：多模型一致且逻辑闭合。
- 弱结论：有支持但证据不足。
- 污染结论：疑似幻觉、套话、时间错配、过度推断。
- 待核验结论：需要外部一手来源确认。

禁止：
- 把模型评测写成主线。
- 假装做过外部搜索。
- 编造材料中没有出现的事实。
- 用户没给明确日期时，自行加入具体日期范围。
- 用空泛形容词替代证据分析。
```

### 5.2 差异追问 Prompt

```text
以下模型在同一问题上出现了差异。
请不要重复原答案，请只解释差异为什么会发生。

请从以下角度判断：
1. 是否因为事实来源不同。
2. 是否因为时间口径不同。
3. 是否因为问题理解不同。
4. 是否因为模型推理链不同。
5. 是否存在 AI 幻觉或污染因素。
6. 哪些说法应该保留，哪些应该剔除。

输出必须结构化，且每个判断都要说明依据来自哪段模型回答。
```

### 5.3 污染剔除 Prompt

```text
请作为审稿人剔除 AI 生成污染。

污染包括：
- 没有证据支撑的具体事实。
- 把推测写成事实。
- 与用户时间范围不一致的信息。
- 安全套话、模板话术、无效总结。
- 逻辑跳跃和因果过度归因。
- 多模型互相重复但仍然无法验证的信息。

请输出：
1. 被剔除内容。
2. 剔除原因。
3. 剔除后仍可保留的判断。
4. 仍需人工核验的问题。
```

### 5.4 最终报告 Prompt

```text
请基于以下材料生成一份“多模型去伪存真情报报告”。

报告必须围绕用户问题给出判断，而不是围绕模型表现写评测。

报告结构：
1. 战情驾驶舱：一句话裁决、可信度、核心矛盾、最大不确定性。
2. 问题补全：展示原始问题如何被补全为可分析任务。
3. 事实地图：多模型确认事实、冲突事实、待核验事实、污染事实。
4. 争议热力：模型差异点、严重度、影响。
5. 证据漏斗：原始 claim 到最终证据的过滤过程。
6. 模型证人画像：各模型在本题中的可信度表现。
7. 源头分析：差异来自哪里，污染剔除后还剩什么。
8. 最终裁决：可以相信什么，不能相信什么，下一步怎么做。

风格要求：
- 咨询报告级别。
- 高信息密度。
- 结论明确但不过度断言。
- 每个判断都要能回到材料。
- 少写空话，多写证据、差异、风险和行动。
```

## 6. 前端组件落地

### 6.1 建议模块拆分

不要把报告渲染继续塞进 `app.js` 或 `ui-wiring.js`。

建议新增：

- `report-schema.js`：报告数据 schema、默认值、归一化。
- `report-presenter.js`：报告弹层 UI 渲染入口。
- `report-charts.js`：SVG/CSS 图表组件。
- `report-exporter.js`：PDF/HTML 导出。
- `report-prompts.js`：最终报告 Prompt 和结构化输出 Prompt。
- `report-metrics.js`：可信度、证据漏斗、模型评分的纯函数。

职责边界：

- Prompt 构造只在 `report-prompts.js`。
- 数据评分只在 `report-metrics.js`。
- DOM 渲染只在 `report-presenter.js`。
- 图表绘制只在 `report-charts.js`。
- 导出逻辑只在 `report-exporter.js`。

### 6.2 第一版必须实现的组件

- `ExecutiveDashboard`：战情驾驶舱。
- `QuestionBriefCard`：问题补全卡。
- `FactTimeline`：事实时间轴。
- `DisputeHeatmap`：争议热力图。
- `DiffInspector`：差异详情侦查台。
- `EvidenceFunnel`：证据漏斗。
- `ModelWitnessRadar`：模型证人画像。
- `FinalVerdictCard`：最终裁决卡。

### 6.3 弹层布局

推荐布局：

- 顶部固定：报告标题、可信度、导出、关闭。
- 左侧固定：章节导航和证据统计。
- 中间滚动：报告正文。
- 右侧浮动：当前章节的图表说明和风险提示。

如果屏幕较小：

- 左侧导航折叠为顶部标签。
- 图表说明下沉到章节内部。
- 差异详情改为抽屉式。

## 7. 导出报告设计

PDF 不能只是网页打印。它应该像一份可以发给客户的咨询材料。

PDF 页面建议：

1. 封面页：标题、用户问题、模型列表、生成时间、可信度总分。
2. 核心结论页：一句话裁决、核心矛盾、最大不确定性。
3. 事实地图页：时间轴和证据矩阵。
4. 争议焦点页：热力图和高风险差异。
5. 去伪存真页：证据漏斗和污染剔除清单。
6. 模型证人页：模型雷达和可信度卡。
7. 最终裁决页：结论、保留意见、下一步行动。
8. 附录页：原始模型回答摘要、追问记录、数据说明。

导出视觉：

- 封面用大面积留白和光晕。
- 每页顶部有小型可信度状态条。
- 关键数字使用大字号。
- 图表占页面中心，文字解释控制在 3 到 5 行。
- 附录可以密集，正文必须高级。

## 8. 实施分期

### Phase 1：报告骨架升级

目标：先解决“报告不清晰、不像专业分析”的问题。

交付：

- 新报告 Prompt。
- 结构化 JSON schema。
- 战情驾驶舱。
- 最终裁决卡。
- 差异详情数据接入。

成功标准：

- 用户打开报告 10 秒内能知道最终判断。
- 报告不再以模型表现为主线。
- 差异点可以点击查看详情。

### Phase 2：证据链可视化

目标：让“去伪存真”过程可视化。

交付：

- 事实时间轴。
- 争议热力图。
- 证据漏斗。
- 污染剔除清单。

成功标准：

- 用户能看出哪些内容被确认、冲突、剔除。
- 每个图表都能点击查看原始模型片段。

### Phase 3：模型证人系统

目标：把模型评价变成可信度支撑。

交付：

- 模型雷达图。
- 模型证人卡。
- 对齐税条形图。
- 追问响应力评分。

成功标准：

- 用户能知道哪个模型在本题更可靠。
- 模型评价不抢主结论。

### Phase 4：咨询级 PDF 导出

目标：让报告可交付、可转发、可收费。

交付：

- PDF 封面。
- 分页排版。
- 图表导出。
- 附录原文。

成功标准：

- PDF 不像网页截图。
- 可以直接发给客户或老板。
- 视觉上具备咨询报告和情报简报质感。

## 9. 验收标准

### 9.1 内容验收

- 是否先回答用户问题。
- 是否明确可信度。
- 是否说明核心矛盾。
- 是否列出多模型一致事实。
- 是否列出差异点和差异原因。
- 是否说明污染剔除过程。
- 是否区分强结论、弱结论、污染结论和待核验结论。
- 是否给出下一步行动建议。

### 9.2 视觉验收

- 第一屏是否有“战情驾驶舱”的压迫感。
- 图表是否服务于判断，而不是装饰。
- 信息密度是否高但不乱。
- 结论、证据、风险是否有清晰层级。
- 弹层是否支持长内容滚动。
- PDF 是否具备可交付质感。

### 9.3 工程验收

- 报告 Prompt 不写在 UI 事件里。
- 报告评分逻辑是纯函数。
- 图表组件可复用。
- 弹层渲染与导出逻辑分离。
- `app.js` 不新增报告业务逻辑。
- 新模块单文件尽量控制在 300 到 500 行以内。

## 10. 一句话目标

最终体验应该是：

`用户感觉自己不是在看 AI 汇总，而是在看一套多模型审讯系统给出的事实裁决。`

如果做到这个层级，这份报告就不只是“炫酷”，而是具备产品溢价感、交付价值和商业说服力。
